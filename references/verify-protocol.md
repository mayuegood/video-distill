# 帧证据纠错协议（verify-protocol）

## 为什么这一层存在

实测对照：人工校对版漏掉了 `都江宴`/`禮賓`/`明江` 三个错字，且渗进了发布版 DIGEST 的引文；同日帧证据纠错做出 49 处改动、47 处有帧文件名可追溯。结论：

- 同音字错误靠听音频永远验不出来，只有画面（板书/字幕）是物证
- 英文漏字（`Harnes`）、文件名误写（`sore.md`→`SOUL.md`）这类错误**只有**视觉证据能锁定
- 不可审计的纠错等于没纠——所以 changes.log 是硬交付物

## Whisper 中文口播的已知错误模式

1. **同音字**：地名/人名/术语重灾区（民江→岷江、禮兵→李冰、菲沙宴→飞沙堰、都將業→都江堰、寶貧口→宝瓶口）
2. **英文漏字/粘连**：Harnes→Harness（一个视频里出现了 13 处）
3. **专有名词/文件名误写**：cloud.md→CLAUDE.md、sore.md→SOUL.md、scale→Skill、馬克當→markdown
4. **全文繁体输出**：格式问题，逐句转简体
5. **口吃/重复**（"會會"）：**保留不动**，这是真实语音不是错误

## 读帧方法

1. 用 agent 的图像能力读帧（Read 工具 / 多模态 analyze，按你所用 agent 的能力走）
2. prompt 要求列出：画面中所有中文文字、所有英文术语、专有名词的标准写法
3. 板书类帧重点记录**专有名词写法**（这是纠错证据的主要来源）；字幕类帧还能提供逐句校对证据

**覆盖率要求**：所有 scene 帧必须看；tick 帧至少每隔一张看一张（000/024/048…）；相邻帧板书内容重复时，确认过专有名词写法后可跳过。

**时间对齐**：帧文件名数字 = 秒数，用 raw.srt 把帧对到具体句子。字幕帧的文字可以直接当该时间点句子的证据。

**定向帧定位法（省力模式）**：视频长或服务不稳时，不必全量扫帧——先把存疑词（UNVERIFIED 项 + 已知误听模式词）在 raw.srt 里 grep 出时间戳，只读命中点 ±24s 的帧（注意 tick 是 TICK_SEC 的倍数，先对齐再找文件）。实测 911s 视频从 92 帧收敛到 ~15 张关键帧。局限：若存疑词全场高频撒布，定向窗口会退化成全量，此时回到分段战术（按时间轴拆两半并行/主 agent 顶上）。

## 改动规则（严格执行）

1. **只改有帧证据或强领域常识支撑的错误**
   - 帧证据：帧里真的出现"岷江"两个字，才能把"明江"改"岷江"，证据=帧文件名
   - 强常识：教科书级事实（如"李冰是都江堰建造者"），可改但证据标 `[COMMON-SENSE]`，不许冒充帧证据
2. **疑似错误无证据**：保留原文 + 句尾标 `[UNVERIFIED: 疑似应为XX]`。不许"顺手改对"——那是把校对变成改写
3. **繁→简**：全文逐句转换，changes.log 顶部注明"全文繁转简"（算格式修复，不算错误改动）
4. **校对不是改写**：不改语序、不删句、不润色、不"优化表达"

## 产出格式

- `verified.txt` —— 纯净简体中文，可安全进入蒸馏层
- `changes.log` —— 每处改动一行：

```
原文 → 改后 | 证据=tick156+168
原文 → 改后 | 证据=[COMMON-SENSE]
（未改动项）原文 | 保留 [UNVERIFIED: 疑似应为XX]
```

末尾统计四行：总改动数 / 帧证据支撑数 / 常识支撑数 / 未验证保留数。

## subagent dispatch 模板（视频长或需并行时）

派 general-purpose subagent，模板（把尖括号替换成实际值；`$SKILL_DIR` = 本 skill 安装目录）：

```
你是视频转录纠错员。工作目录：<out_dir>/

## 背景
一个讲解 <视频主题一句话> 的中文视频（<时长>秒）已经过 Whisper 转录。
转录有两个已知缺陷：① 输出是繁体中文；② 同音字误写。
现在你有视频关键帧作为视觉证据，要产出可信的纠错版。

## 输入（先读任务书）
1. <out_dir>/transcript/verify-task.md —— 完整任务书
2. <out_dir>/transcript/raw.txt / raw.srt —— 初稿 + 时间轴
3. <out_dir>/frames/ —— tickNNN.jpg（每N秒一张）+ sceneNNN.jpg（场景切换帧）

## 看帧方法
用你手头的多模态图像能力读帧（Read 工具读 jpg / analyze_image API 均可），
prompt 要求列：画面所有中文文字、英文术语、专有名词标准写法。
覆盖率：全部 scene 帧 + tick 至少每隔一张。

## 纠错规则
1. 只改有帧证据或强领域常识支撑的错误（常识标 [COMMON-SENSE]）
2. 疑似错误无证据：保留 + 句尾 [UNVERIFIED: 疑似应为XX]
3. 繁体→简体全文转换（顶部注明）
4. 不改语序、不删句、不润色

## 输出（写到 <out_dir>/transcript/）
verified.txt + changes.log（每处一行：原文 → 改后 | 证据；末尾四行统计）

## 收尾自检（必做，prove-it-works）
写完上述产物后跑:
    bash "$SKILL_DIR/scripts/verify-output.sh" <out_dir>
exit 0 才算完成; FAIL 项修复后重跑。不许带着 FAIL 汇报完成。

完成后汇报：改动总数、证据分布、帧里实际看到的板书文字清单、**自检结果（PASS/FAIL 数）**。
```

主 agent 收到结果后**抽查**：随机挑 3 处改动，自己读对应帧验证证据真实性；**并亲自重跑一次 `verify-output.sh <out_dir>`（完整模式，不带 --stage）确认 exit 0**——subagent 自报"自检通过"不算数（self-report 不是证据），主 agent 眼见 exit 0 才放行进 ④。
